# SWE.3 Detailed design and units

DependencyManifest parses a fixed schema with exact filenames, versions, SHA-256 values, licenses, and source provenance. ToolchainProbe accepts explicit prefix and manifest paths, resolves no network resource, verifies every package hash against the separately retained package files, probes required tools safely, checks headers/libraries and pkg-config versions, and returns deterministic diagnostics. The root CMake file enforces C++20, warning policy, test enablement, and an optional future X-COM subtree without inventing source placeholders. Documentation states limits and offline reconstruction steps.

- XCOM-PARSER-DIAGNOSTICS: Modify only scripts/xcom_dependency_preflight.py. Harden existing manifest parsing and diagnostics without adding package-payload extraction or CMake changes. Use immutable typed manifest records; validate the top-level JSON shape, exact record fields, SHA-256 syntax, positive sizes, duplicate filenames, duplicate locked package names, and the exact twelve-entry lock. Anchor all tool/header/pkg-config version checks so 3.12.40 cannot satisfy 3.12.4. Convert expected missing-file, permission, UTF-8/JSON, subprocess, and timeout failures into stable classified diagnostics and nonzero exits. Add useful module/class/function docstrings and table-driven self-tests for these cases. Make the executable script pass Ruff and mypy strict. Preserve the accepted CLI and offline/no-install behavior; edit no other path.; owned paths: scripts/xcom_dependency_preflight.py
- XCOM-PAYLOAD-BINDING: Modify only scripts/xcom_dependency_preflight.py after the parser task. Bind the supplied prefix to the exact admitted .deb payloads. Verify all twelve sibling package files by size and SHA-256, use dpkg-deb in a temporary directory to extract a reference tree without installing anything, and compare every required executable, header, library, symlink target, and pkg-config artifact used by admission against that reference. Report missing dpkg-deb, extraction failure/timeout, unreadable files, type differences, content differences, and symlink differences with deterministic classified diagnostics. Add focused self-tests with tiny controlled fixtures and keep Ruff/mypy strict clean. No network, install, CMake, docs, specs, or runtime behavior.; owned paths: scripts/xcom_dependency_preflight.py
- XCOM-CMAKE-POLICY: Modify only CMakeLists.txt, cmake/, and scripts/xcom_dependency_preflight.py. Enforce C++20, the accepted warning set with warnings as errors, testing, Ninja-compatible configuration, and explicit offline dependency discovery. Add a generated compile-only probe built by CMake with CMake-selected CXX and machine-readable policy evidence. Update preflight integration to configure and build that probe, verify the recorded compiler/policy, and classify failures. Preserve the optional future src/xverse/xcom subtree. Add no runtime sources and edit no docs/specs/architecture.; owned paths: CMakeLists.txt, cmake, scripts/xcom_dependency_preflight.py
- XCOM-RECONSTRUCTION-DOCS: Modify only docs/engineering/xcom/dependency-lock.md and build-environment.md. Record exact public Ubuntu Jammy retrieval coordinates for all twelve packages, hashes, licenses, generated-code provenance, deterministic offline dpkg-deb extraction/provisioning commands, LD_LIBRARY_PATH and other required variables, and python3 >=3.11. State ABI limits, prototype maturity, classified failures, package-hash versus installed-payload verification, and a requirement-to-check traceability table. Edit no code/specs/architecture.; owned paths: docs/engineering/xcom/dependency-lock.md, docs/engineering/xcom/build-environment.md
