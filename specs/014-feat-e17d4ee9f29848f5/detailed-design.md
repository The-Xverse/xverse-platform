# SWE.3 Detailed design and units

Introduce bounded immutable provider capability and limit values created through validating factories. Define a source-level CommunicationProvider interface with explicit describe, prepare, activate, submit, receive, drain, close, state, and reconcile operations; document that this is not a stable ABI and that the caller keeps registered provider objects alive longer than their composition. ProviderComposition owns only fixed registration and route-binding records, issues private-construction handles with composition identity, provider identity/version, lifecycle controller identity, route identity/digest/generation, endpoint identities/generations, and provider-resource generation, and serializes each operation. It consults LifecycleController snapshots before preparation, activation, submission, drain, and close so stale or changed generations never flow. Provider preparation is side-effect bounded and emits no item. LoopbackProvider implements the interface with compile-time maximum route and queue arrays plus caller-selected smaller nonzero limits. Each active route has a deterministic FIFO; full means reject-new with a stable saturation outcome and no mutation. Receive is pull-based and returns owned item/outcome values. Drain blocks new submissions and preserves queued items for consumption; close is permitted only after the queue is empty, unless an explicit discard operation is designed and tested as a distinct outcome. Reconciliation accepts only exact still-owned provider handles and reports stale or absent resources. Existing core types and lifecycle public behavior remain unchanged unless a minimal diagnostic extension is necessary, in which case exact earlier tests and code meanings must be preserved. Add strict public Doxygen for ownership, lifetime, thread-safety, failure, and maturity.
