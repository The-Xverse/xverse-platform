# SWE.2 Software architectural design

Adds the first data-plane realization beneath the accepted X-COM value and lifecycle layers. ProviderComposition explicitly registers caller-supplied source-linked providers through a documented C++ source contract and fixed registry. A ProviderDescriptor declares stable identity/version, supported interaction kinds and policies, and hard resource limits. Preparation validates a RouteSpec and exact lifecycle bindings with no traffic side effect. Activation returns an opaque provider-route handle bound to the provider instance and exact route/endpoint generations. Submission reauthenticates active lifecycle state and immutable CommunicationItem provenance before dispatch. The owned LoopbackProvider uses fixed route slots and fixed per-route FIFO storage, rejects newest-on-full, and offers pull-based receive so no callback executes under a lock. Drain rejects new submissions while queued items can be consumed under a declared disposition; close releases only the exact generation. No address, socket, discovery, dynamic library, XDL compiler, tool, observer, or legacy boundary is added.
